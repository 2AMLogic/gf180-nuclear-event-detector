# 0009 — Area

- **Date:** 2026-11-19
- **Status:** proposed (flips to `RATIFIED` in the carrying PR, after the two independent reviews — see [target-spec.md](../target-spec.md))
- **Decides:** the core-area budget the layout is graded against, and what counts inside it.
- **Grades:** target-spec.md row 9 (AREA).

## Context

The part must stay small enough to drop into a system as a component — the AREA row is the bound that keeps the design honest as the other rows pull in different directions (bigger sensing junction, wider immunity margins, more test circuitry). The DRAFT table set ≤ 0.10 mm² core with a ≤ 0.05 mm² stretch.

## Options considered

1. **≤ 0.10 mm² core** — silicon area inside the core ring, pad ring and external components excluded (the DRAFT value, with the definition made explicit).
2. **≤ 0.10 mm² total including the pad ring** — simpler to measure, but the ring depends on packaging choices outside this part's control and would couple the bound to pin count.
3. **No area bound** — rejected: without a bound, area silently absorbs every other row's fallback activation.

## Choice

Option 1, confirmed from the DRAFT table: **core area ≤ 0.10 mm²** — the silicon inside the core ring, excluding the pad ring and all external components (the threshold resistor, the width capacitor, the flag pull-up). **Stretch: ≤ 0.05 mm² core. Fallback: ≤ 0.20 mm² core, via a new decision record.**

- The sensing junction's minimum area from record [0001](0001-sensing-element.md) (≥ 1,000 µm² = 0.001 mm², stretch ≥ 10,000 µm² = 0.01 mm²) is inside this budget with an order of magnitude of room; the comparator, logic and stretch circuitry share the remainder.
- Excluding the pad ring keeps the bound about the design, not the package; the pin count that drives the ring is bounded by the records themselves (supply, sense, threshold, width, TEST, flag).

## Fallback

**≤ 0.20 mm² core** via a new decision record if the DRC-clean layout misses the 0.10 mm² bound — recorded together with the measured area and the row(s) whose fallback activations forced the growth.

## Evidence (public primary sources, accessed 2026-11-19)

- The budget's composition rests on the sibling records: sensing-junction area ([0001](0001-sensing-element.md)), external-component exclusions ([0002](0002-threshold.md), [0004](0004-flag-output.md)), pin set ([0005](0005-built-in-test.md), [0007](0007-supply-domain.md)).
- No PDK number is cited for a *budget* — the area bound is a product decision; the PDK's role is in the *measurement* below.

## Verification

Not a simulation. The post-layout, DRC-clean GDS is measured with klayout-tools and the area recorded under `measurements/` as append-only evidence; the recorded value is graded against this row. Until a layout exists, the README's status block carries the literal "not yet measured" — this row's bound is a target, never back-filled into a status field.

## Consequences

- Every fallback activation elsewhere in this specification is re-checked against this row before its own record is ratified — area is where scope creep lands.
- The stretch goal (≤ 0.05 mm²) is graded the same way, when the layout first meets the target bound.
